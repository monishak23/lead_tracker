## Prompts
User prompts given to Claude, in order, that produced the current codebase:

1. > Act as a full stack developer and help me to build a lead generation
   > application. Tech stacks to be used react.js, node.js and postgreSql.
   > Below are the fields in leads table. Fields: Name, Email, Phone,
   > Status, Created At. Methods include creat lead, Update Lead Status,
   > Search Leads, List Leads. Generate foundational database architecture
   > with postgresql. STRICT BOUNDARY CONSTRAINT: Implement ONLY the fields
   > and features explicitly stated.

2. > keep both phone and email as unique.

## Key Engineering Decisions
- **UUID primary key** (`gen_random_uuid()` via `pgcrypto`) — not part of
  the original field list, but a primary key is required by the relational
  model; UUID was chosen over a serial integer to avoid exposing sequential
  IDs.
- **`status` as a Postgres ENUM** (`New`, `Contacted`, `Qualified`, `Lost`)
  rather than free-text, so invalid values are rejected at the database
  level. Values were not specified by the user and should be confirmed/
  adjusted before production use.
- **`email` UNIQUE** — added on the assumption that email is the natural
  de-duplication key for a lead; confirmed with the user.
- **`phone` UNIQUE** — added second, at the user's explicit request, after
  discussing the trade-off that unnormalized phone formats (e.g.
  `9876543210` vs `+91 9876543210`) can still slip through as distinct
  values.
- **`created_at` set via `DEFAULT now()`**, not accepted from the client,
  so creation time can't be spoofed by the API caller.
